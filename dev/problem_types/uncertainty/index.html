Stochastic, Robust and Partially Observable Games

Three problem types layer uncertainty on top of a nominal deterministic game. Each wraps the nominal game (nominal_game or underlying_game) instead of copying it, so everything that works on the nominal game still applies to it.

TypeUncertaintyWrapper argumentsConsumed by
StochasticGameProblemrandom process noise (Itô diffusion or a covariance)nominal game + ProcessNoiseModel or an ItoSDEDynamicsSFNELQ (additive noise); determinize
RobustGameProblembounded, non-probabilistic disturbancenominal game + DisturbanceSet(w_min, w_max)tube-based solvers such as DynamicTubeMPC (the tube parameters carry the disturbance bound), the Benchmarks robustness challenge
POGameProblempartial or noisy observationunderlying game + one observation model per playerinformation-structure queries; no built-in forward solver

required_capabilities adds :Stochastic, :RobustDisturbance or :PartiallyObservable to those of the nominal game, so solve's capability check reports a solver that does not handle the extension.

Stochastic games

DifferentialGamesBase.StochasticGameProblem — Type
StochasticGameProblem{T} <: AbstractStochasticGame{T}

A deterministic nominal_game with stochastic dynamics layered on top of its drift. Nothing about the nominal game's dynamics/objectives/constraints is duplicated; stochastic_dynamics wraps nominal_game.dynamics as the drift of an ItoSDEDynamics (or, for the Phase 1 POMDPs.jl adapter, is a MarkovKernelDynamics).

Fields

  • nominal_game::AbstractDeterministicGame{T}
  • stochastic_dynamics::AbstractStochasticDynamics{T}
source
DifferentialGamesBase.ProcessNoiseModel — Type
ProcessNoiseModel{T}

Backward-compatible data holder for additive Gaussian process noise on the joint state: x_{k+1} = f(x_k, u_k) + w_k, w_k ~ N(0, Σ). On its own it carries no drift information; StochasticGameProblem(nominal_game, ::ProcessNoiseModel) is what turns it into the ItoSDEDynamics that reproduces this exact semantics, using nominal_game.dynamics (must be LinearDynamics) as the drift.

Distinct from SharedObservation/PrivateObservation's noise fields, which model measurement noise (what a player observes about the state), not dynamics noise (how the true state evolves) — see the design note in abstract/information_structure.jl.

Fields

  • Σ::Union{Matrix{T}, Vector{Matrix{T}}} : Process noise covariance, either constant (LTI, supported) or one matrix per time step (LTV — not yet supported by the ItoSDEDynamics conversion; raises an error, see docs/src/api/stochastic.md Phase roadmap).
source

With additive noise the problem is certainty equivalent: the feedback Nash gains equal those of the deterministic game and the noise only adds an expected-cost term. SFNELQ exploits this. Multiplicative (state- or control-dependent) noise is representable through ItoSDEDynamics but no solver here handles it.

using DifferentialGames, LinearAlgebra

A = [1.0 0.1; 0.0 1.0]
B = [reshape([0.0, 0.1], 2, 1)]
nominal = LQGameProblem(A, B, [Matrix(1.0I(2))], [fill(0.1, 1, 1)], [Matrix(5.0I(2))], [1.0, 0.0], 1.0; dt = 0.1)

stochastic = StochasticGameProblem(nominal, ProcessNoiseModel(Matrix(0.01I(2))))
(certainty_equivalent = is_certainty_equivalent(stochastic),
 multiplicative_noise = has_multiplicative_noise(stochastic),
 required = required_capabilities(stochastic))
(certainty_equivalent = true, multiplicative_noise = false, required = [:LQGame, :UnconstrainedGame, :DiscreteTime, :Stochastic])
sol_det = solve(nominal, FNELQ())
sol_sto = solve(stochastic, SFNELQ())
(deterministic_cost = get_cost(sol_det, 1), expected_cost = get_cost(sol_sto, 1),
 noise_cost = sol_sto.solver_info[:noise_cost][1])
(deterministic_cost = 6.096811921788617, expected_cost = 6.761334279768616, noise_cost = 0.6645223579799989)

The expected cost exceeds the deterministic one by exactly noise_cost (checked in the solver's tests).

Determinization and chance constraints

determinize(stochastic; propagator, evaluator, risk_allocation) compiles a stochastic game into a deterministic GameProblem whose state is the belief $z=(\mu,\Sigma)$ (the mean and the flattened covariance), propagating the covariance with a LinearizedGaussianPropagation (or an unscented or particle propagator). A ChanceConstraint(constraint, risk) states $\Pr[g(x,u)\le 0]\ge 1-\varepsilon$ and is compiled into a deterministic residual on the belief by compile_chance_constraint with a chance evaluator (Gaussian quantile, Monte Carlo or scenario) and a risk allocation (uniform, fixed or optimized).

cc = ChanceConstraint(PrivateInequality(1; func = (x, u, p, t) -> [x[1] - 2.0], dim = 1), 0.05)
determinized = determinize(stochastic)
(chance_constraint = cc, belief_state_dim = state_dim(determinized))
(chance_constraint = ChanceConstraint{PrivateNonlinearInequality{Main.var"#2#3", Nothing}}(risk=0.05, scope=:private), belief_state_dim = 6)
Current limitation

The determinized game's dynamics is a discrete-time map wrapped in CoupledNonlinearDynamics, which the solvers integrate as a continuous-time right-hand side. As a result solve(determinize(sg), iLQGames()) currently fails (an InexactError while indexing the time step), contrary to the determinize docstring. The construction itself works; solving it needs a discrete-time nonlinear dynamics type, tracked in the audit.

For solving stochastic games end to end — risk budgets, shared observations, and what each guarantee means — see How to solve a stochastic game. The complete stochastic API (SDE dynamics, discretization, propagators, chance evaluators, the POMDPs.jl adapter) is documented in the DifferentialGamesBase.jl API reference.

Robust games

DifferentialGamesBase.DisturbanceSet — Type
DisturbanceSet{T}

Box bound on an additive disturbance: w ∈ [w_min, w_max] (component-wise), worst-case rather than distributional. This is what tube-based/min-max solvers (e.g. DynamicTubeMPC in DifferentialGamesBaseSolvers.jl) need — a set, not a covariance.

Fields

  • w_min::Vector{T}
  • w_max::Vector{T}
source
DifferentialGamesBase.RobustGameProblem — Type
RobustGameProblem{T} <: AbstractStochasticGame{T}

A deterministic nominal_game subjected to a bounded (non-probabilistic) additive disturbance on the joint dynamics.

Fields

  • nominal_game::AbstractDeterministicGame{T}
  • disturbance::DisturbanceSet{T}
source
robust = RobustGameProblem(nominal, DisturbanceSet([-0.05, -0.05], [0.05, 0.05]))
(robust, required_capabilities(robust))
(RobustGameProblem{Float64} wrapping GameProblem{Float64} with 1 players [LQ, Unconstrained] [disturbance dim=2], [:LQGame, :UnconstrainedGame, :DiscreteTime, :RobustDisturbance])

A robust game describes worst-case rather than distributional uncertainty. The set is what tube-based and min-max methods need: the disturbance bound that sizes the tube.

Partially observable games

DifferentialGamesBase.POGameProblem — Type
POGameProblem{T} <: AbstractPartiallyObservableGame{T}

A deterministic underlying_game in which each player observes according to its own PrivateObservation or SharedObservation (reused from information_structure.jl, not duplicated).

Fields

  • underlying_game::AbstractDeterministicGame{T}
  • observation_models::Vector{<:Union{PrivateObservation, SharedObservation}} : one entry per player, in player-index order.
source

Each player observes $y=h(x,v,p,t)$ through a PrivateObservation (own signal; strategies depend on beliefs) or a SharedObservation (a common signal), defined in Information Structures:

position_only = (x, v, p, t) -> x[1:1]                           # observe the first state, noisily
po = POGameProblem(nominal, [PrivateObservation(position_only, 1, fill(0.01, 1, 1))])
(po, required_capabilities(po))
(POGameProblem{Float64} wrapping GameProblem{Float64} with 1 players [LQ, Unconstrained] [1 observation models], [:LQGame, :UnconstrainedGame, :DiscreteTime, :PartiallyObservable])

No solver in this ecosystem consumes a POGameProblem directly. The type fixes the interface so that belief-space solvers, and the restrict_observation challenge of the Benchmarks package, can be written against it.
