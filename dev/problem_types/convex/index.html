ConvexGameProblem

A convex game has objectives that are convex in each player's own decision and closed convex constraint sets. Existence of a Nash equilibrium follows from Rosen's theorem; uniqueness holds under diagonal strict convexity of the pseudo-gradient ([Ros65]). With a shared coupling constraint the natural solution concept is a variational generalized Nash equilibrium ([FK10]).

Constructors

DifferentialGamesBase.ConvexGameProblem — Type
ConvexGameProblem{T} <: AbstractConvexGame{T}

General convex N-player game: all player objectives are convex in own decisions and all constraint sets (private and shared) are convex.

Convexity verification

  • LQ objectives (LQStageCost + LQTerminalCost): verified automatically. Their constructors already enforce R ≻ 0, Q ≽ 0, Qf ≽ 0, which suffices for convexity in the control when dynamics are linear.
  • Constraints: verified automatically by checking is_convex(c) on every constraint. ControlBounds and StateBounds are marked convex; all others default to false and require assume_convex=true.
  • Nonlinear objectives or non-convex-tagged constraints: require the caller to pass assume_convex=true to suppress the check.

Fields

  • n_players: number of players
  • forward_game: underlying GameProblem{T} (dynamics, objectives, constraints)
  • is_strictly_convex: true if the pseudo-gradient F = (∇ₓᵢJᵢ)ᵢ satisfies Rosen's diagonal strict convexity condition, guaranteeing a unique NE

Equilibrium guarantees

  • Existence: always guaranteed (objectives convex + closed convex sets)
  • Uniqueness: guaranteed when is_strictly_convex == true (Rosen 1965, Thm 2)

References

Rosen, J.B. (1965). Existence and uniqueness of equilibrium points for concave N-person games. Econometrica 33(3), 520–534.

source

Convexity is verified automatically for LQ objectives and for constraints tagged is_convex (box bounds). For nonlinear objectives or untagged constraints pass assume_convex = true, which asserts convexity without checking it.

Example: a static two-player game

YiPavel works on static decisions, so a game with one time step is used and each player's control is its decision. The costs are supplied to solve through cost_fns, one function of all players' decisions per player:

\[f_1(u_1,u_2)=\tfrac12(u_1-2)^2+\tfrac c2(u_1+u_2)^2,\qquad f_2(u_1,u_2)=\tfrac12(u_2-1)^2+\tfrac c2(u_1+u_2)^2,\quad c=0.1 .\]

Setting both gradients to zero gives the Nash equilibrium $(u_1^*,u_2^*)=(1.75,\,0.75)$.

using DifferentialGames, LinearAlgebra

T = Float64
frozen = (x, u, p, t) -> zeros(T, length(x))                # trivial dynamics: the decision is the control
mkplayer(i) = PlayerSpec{T}(i, 1, 1, zeros(T, 1), frozen,
    PlayerObjective(i, LQStageCost(zeros(1, 1), fill(1e-8, 1, 1)), LQTerminalCost(zeros(1, 1))), T[])

game = ConvexGameProblem([mkplayer(1), mkplayer(2)], T(1.2), T(1.0); assume_convex = true)   # tf, dt: one step

c  = 0.1
f1 = (s1, s2) -> 0.5 * (s1[1] - 2.0)^2 + 0.5 * c * (s1[1] + s2[1])^2
f2 = (s1, s2) -> 0.5 * (s2[1] - 1.0)^2 + 0.5 * c * (s1[1] + s2[1])^2

sol = solve(game, YiPavel(; max_iter = 5000, τ = 0.05, ν = 0.02, σ = 0.05); cost_fns = Function[f1, f2])
u = [get_trajectory(sol, i).controls[1] for i in 1:2]
@assert isapprox(u, [1.75, 0.75]; atol = 1e-2)
(converged = sol.converged, iterations = sol.iterations, decisions = round.(u; digits = 4))
(converged = true, iterations = 205, decisions = [1.75, 0.75])

The solution is compared with the analytical equilibrium, which is the right check for a method whose stopping rule is a step size.
