# Equilibrium Concepts

A solver's *name* does not determine which equilibrium it computes. This page defines the concepts; the [solver selection guide](../basics/solver_selection.md) maps each solver to the concept it targets, and each solver page states what is and is not guaranteed.

## Open-loop Nash equilibrium (OLNE)

The concepts below follow the standard treatment in [BasarOlsder1999](@cite).

Strategies are control *sequences*. A profile ``(\mu^{1*},\dots,\mu^{P*})`` is an OLNE if for every player ``i``

```math
J_i(\mu^{i*}, \mu^{-i*}) \le J_i(\mu^{i}, \mu^{-i*}) \quad \text{for all admissible } \mu^i,
```

with the state trajectory generated by the dynamics. Targeted by [ALGAMES](../solvers/algames.md) (`equilibrium_type = :OpenLoopNash`-style results, `OpenLoopStrategy`).

## Feedback Nash equilibrium (FNE)

Strategies are functions of the current state, ``u_k^i = \gamma_k^i(x_k)``. A profile ``\gamma^*`` is a (Markov-perfect) FNE if at every stage ``k`` and every state ``x``, no player can reduce its *cost-to-go* by deviating from ``\gamma_k^{i*}`` at that stage and onward, given the others' strategies. The cost-to-go satisfies the coupled Bellman recursion in [Optimality Conditions](optimality_conditions.md). Targeted exactly for LQ games by [FNELQ](../solvers/fnelq.md) (`:FeedbackNash`), and approximately (locally) for nonlinear games by [iLQGames](../solvers/ilqgames.md).

Open-loop and feedback equilibria generally differ, even for the same game.

## Generalized Nash equilibrium (GNE)

With shared constraints the feasible set of a player depends on the others' decisions. A profile ``(u^{i*})`` is a GNE if each ``u^{i*}`` solves

```math
\min_{u^i} J_i(u^i, u^{-i*}) \quad \text{s.t. } h_i(u^i)\le 0,\; g(u^i, u^{-i*}) \le 0 .
```

Generalized Nash equilibria are typically not unique: a continuum of GNEs can exist [FacchineiKanzow2010](@cite).

## Variational and normalized equilibria

A *variational* GNE (VGNE) is a GNE at which all players share the same Lagrange multiplier ``\lambda`` for each shared constraint. Equivalently it solves the variational inequality built from the pseudo-gradient ``F(u) = (\nabla_{u^i} J_i)_i`` over the shared feasible set. A *normalized* Nash equilibrium [Rosen1965](@cite) allows multipliers that are fixed scalings ``\lambda/r_i`` of a common ``\lambda``; the variational case is ``r_i \equiv 1``. These are the natural *selection* of one equilibrium from the continuum. [YiPavel](../solvers/yipavel.md) ([YiPavel2017](@cite)) declares `:VariationalNash` and `:GeneralizedNash` capabilities. For [ALGAMES](../solvers/algames.md), identical multiplier updates on shared constraints are the mechanism by which a variational/normalized equilibrium is sought, but this documentation does not claim the returned point is one (see the solver page).

## Equilibrium, approximation and stopping criterion

Three different things are easy to conflate:

| Concept | Meaning | Where it appears |
|---------|---------|------------------|
| **Equilibrium definition** | the mathematical object above | this page |
| **Numerical approximation** | what the algorithm computes (e.g. a local LQ approximation, a penalized KKT system) | solver pages |
| **Stopping criterion** | the test that sets `sol.converged` | solver pages |

For instance, iLQGames stops when consecutive trajectories change by less than `ε_conv`. That is not, by itself, proof of a Nash equilibrium. ALGAMES stops on stationarity, dynamics and constraint residuals (`opt_vio`, `dyn_vio`, `con_vio`), which are equilibrium *residuals* of its penalized system, evaluated only at nodes ``1..N`` (see its page). The `equilibrium_type` field of a `GNEPSolution` records the *intended* concept (`:FeedbackNash`, `:OpenLoopNash`, `:GeneralizedNash`, `:Approximate`, `:Unknown`), not a verification.
